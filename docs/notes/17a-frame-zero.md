## 1. Артефакты

| Скрипт | Роль | Выходы/коды |
|---|---|---|
| `scripts/stage-session.sh <image> <stage-dir> [cmd...]|-` | единственный вход для сессии: свежий mdconfig → rw-маунт (allow_other, демон под rctl-капом) → команда/интерактивный маркер → RSS каждые 10 с → canary → umount → fsck → вердикт | сессия в `tmp/stage-sessions/<ts>/`; коды: 0 чисто, 1 маунт, 2 fsck грязный, 3 команда |
| `scripts/stage-canary.sh <mnt> <log> [--auto-stop] [--probe-dir D]` | L0-детектор зависаний: statfs+touch пара каждые 1 с; >10 с (или таймаут 12 с) = stall | L0 (алерт) → повторный подряд → L1 (+ `doas umount -f` с `--auto-stop`, выход 42) |
| `scripts/stage-sentinel.sh build|verify <mnt> <file>` | L2-контроль данных: 64 sha256, стратифицированных по глубине (8 верх / 24 сред / 32 глубок, классы = различные глубины /3) | verify: 0 чисто, 1 дрифт (missing/changed); пустой набор = 64 |
| `scripts/regression.sh [quick] [--rss-capture] [--op-census] [--kill-drill]` | батарея: кв+гейты; drill = kill -9 ПОСЕРЕДИНЕ шторма (≥5000 файлов, шторм жив) + цикл восстановления | ненулевой = красная ночь, ступени стоят |

## 3. Как сессии подключаются к фазам

- **Ф1 посев**: снапшот → образ → `stage-session.sh img mnt -` (интерактивный маркер;
  оператор работает с маунтом, `echo done|fail > <sess>/done` завершает) → sentinel build
  на смонтированной копии = манифест; после посева — verify. Дрель одноразовости тоже
  через обёртку (код 2 на грязном образе = стоп).
- **Ф2 read-soak**: сессии только в обёртке; RSS-график из `rss.log` — ответ на
  «события на ГБ чтения» (плато-кэш vs линейная утечка); после каждого umount — fsck -n
  вердикт; canary следит за stall'ами скана.
- **Ф3 запись под сканом**: плановая kill-9-дрель = `regression.sh quick --kill-drill`;
  p99-гистограмма = `--op-census` (BCACHEFS_LOG=debug → per-request трейс);
  create/rename/unlink/ГБ счётчики = op-census.log суммарно.
- **Ф4 сервисы**: каждый сервис (navidrome → qbittorrent → amuled → samba) работает в
  своей сессии обёртки; откат ступени = config-flip на NFS-путь (мост живёт).
- **Ночной прогон**: `regression.sh --kill-drill --op-census --rss-capture` (без quick —
  раз в неделю с cargo-тестами + pjdfstest); красная ночь = морозка ступеней.

## 4. Ключевые решения и находки

1. **Патч 057 сломал userspace repair-fsck (ЭСКАЛАЦИЯ оркестратору).** `read_super`
   теперь не ставит `BLK_OPEN_WRITE` для read_only-открытий, а fsck открывает именно так
   (read_only БЕЗ nochanges): любая попытка записи суперблока → EBADF →
   `erofs_recovery_cancelled`/`erofs_sb_err` на ЛЮБОМ образе (чистом и грязном),
   подтверждено на /dev/md (root) и на файле-образе (user). Q1 crash-gate проходил
   ДО 057. Лечение (не в скоупе Ф0 — сборка запрещена): вернуть WRITE, когда
   `opts.fsck` (сузить инвариант 057 до «ro-mount без fsck»), патч + тест в батарею.
2. **Оракул вердикта = `fsck -n` (check-only), журнал-грязь = чисто.** fsck -n
   реплеит журнал в памяти: kill -9 → umount -f → `recovering from unclean shutdown` →
   `clean shutdown complete`, rc 0; ненулевой rc = повреждение сверх журнала.
   Дисковый реплей принадлежит маунту (демон с rw-fd): kill -9 → umount -f → fsck -n rc 0
   → remount rw (реплей) → umount → fsck -n rc 0 — проверено целиком. Все fsck-гейты
   батареи и обёртки идут под `rlimit-run.sh 1024`.
3. **Ro-гейт стадии 4 переписан под семантику 057.** Старый гейт ждал отказа маунта на
   ro-устройстве; после 057 ro-маунт законно поднимается (инвариант «fd = write
   capability», окно на живом пуле). Новый гейт: ro-маунт ПОДНИМАЕТСЯ, запись получает
   честный `Read-only file system` (EROFS).
4. **`format` не принимает colon-синтаксис** (`dev1:dev2` = один путь → ENOENT, даже из
   root); `mount`/`fsck` принимают. Стадия 5 форматирует раздельными аргументами.
5. **Canary-проба убивается SIGKILL.** `timeout` шлёт SIGTERM только обёртке sh — та
   ждёт застрявших в ядре df/touch: измерено 40–60 с на пробу, L1 был недостижим.
   `timeout -s KILL 12` — dt ровно 12 с; осиротевшие df/touch висят в ядре до CONT/umount
   (ограничено, ожидаемо, после — умирают; замер: 0 остатков).
6. **Доступ пользователя: `fuse,allow_other` + `.stage`.** Философия порта — allow_other
   c default_permissions; права остаются posix'ными. Обёртка создаёт `$MNT/.stage`,
   chown вызывающему → команда сессии и канарейка пишут как пользователь, проба
   канарейки реально ходит через FUSE-write, а не умирает на EACCES в корне fs.
7. **Освобождение md с ретраями.** `mdconfig -d` гонкует с закрытием устройства демоном
   (EBUSY): detach_md до 10 попыток, иначе ГРОМКОЕ предупреждение (не молча).
8. **umount -f на SIGSTOP-нутом демоне занимает ~60 с** (vflush-таймаут FreeBSD):
   авто-стоп L1 работает, но не мгновенно — ожидаемо, зафиксировано.
9. Замечание по гигиене: на хосте висит посторонний `md0` → `/tmp/bch-057.img`
   (наследие работы над 057, не Ф0) — не трогал, владельцу прибрать.

## 5. Dry-run-приёмка (2026-11-03, все зелёные)

**(a) Пустой стейдж — зелёный.** `stage-session.sh` на свежем 512m-образе, команда
`sleep 2; echo probe-ok > $STAGE_WORK/probe; cat ...`: **exit 0, VERDICT 0 — clean**,
fsck -n `clean shutdown complete`; canary: `PROBE ok dt=0s`; RSS 56484 kB (1 проба,
короткая сессия); md освобождён, fuse-маунтов нет. Дополнительно: режим интерактивного
маркера — операционная проба на маунте, `done` → exit 0 clean. Негативный путь: упавшая
команда → VERDICT 3 (наблюдалось до фикса прав, артефакт сохранён).

**(b) Грязная дрель — зелёная.** `regression.sh quick --kill-drill --rss-capture
--op-census` → **ALL GREEN, exit 0**: kill -9 демона посередине шторма (files=9374,
storm_alive=yes, waited=1s; после килла — `Device not configured` на продолжающихся
записях = доказательство килла под нагрузкой); recovery fsck -n: `recovering from
unclean shutdown` → `clean shutdown complete`; цикл: remount rw → files=9209
(≈165 хвоста журнала из 9374 — согласуется с Q1) → rw-probe ok → umount → fsck -n clean;
оп-цензус: 8 типов / 47653 ops (CREATE/WRITE/LOOKUP/GETATTR ≈ по 11.4k, RELEASE −1,
READDIR 93, OPENDIR 2, FLUSH 1 — сигнатура шторма); RSS max 59924 kB; ro-гейт: маунт
поднялся ro, запись → `Read-only file system`; multi-device чисто.

**(c) Канарейка — стреляет.** SIGSTOP демона на живом маунте: **L0 ALERT через ~13–15 с**
(dt=12 с на пробу, бюджет ≤15 с выдержан); L1 STALL на ~26 с (consecutive=2,3,4…);
SIGCONT → RECOVERED через 1 с, touch пользователем после CONT работает, 0 осиротевших
процессов. Раунд с `--auto-stop`: **canary_exit=42**, `umount -f` исполнен канарейкой
(UMOUNTED-BY-CANARY; ~60 с на vflush — см. §4.8), состояние после — чистое.

**(d) Сентинелы (доп. доказательство).** Дерево 30/90/180 файлов глубин 1/2/5: build →
**ровно 8×d1 / 24×d2 / 32×d5** (64 строки); verify ok=64 rc 0; дрифт (изменён 1,
удалён 1) → missing=1 changed=1, **rc 1**; выбор детерминирован (перестройка того же
состояния = тот же набор путей в том же порядке).
