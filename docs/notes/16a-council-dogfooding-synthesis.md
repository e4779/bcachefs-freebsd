# 15b — Совет по адаптации: решение (синтез пяти докладов)

**Контекст.** Владелец оспорил план 15a (14-дневный staging-soak): реальные нагрузки сейчас, чинить по мере находок, stash-GPU первым. Пять мест совета: data-safety аудитор, архитектор постепенной адаптации, прагматик нагрузки (позиция владельца), архитектурный реалист, скептик по требованиям. Документ исполняемый: оркестратор действует прямо из него.

## 1. Вердикты

## 2. Отклонённые и неподтверждённые утверждения

| Утверждение | Статус | Действие |

Опора (подтверждено репо): окно 27/27 sha256 / ноль записей / откат 45 с / kill-протокол сработал правильно; dirty-ro 417k файлов, replay чистый; multi-device гейт; `regression.sh` уже кодирует фазу-0 гейты; rctl активен; fsck только на Linux; extattr vnops отсутствуют; TTL=Duration::MAX — усилитель тишины attrs-багов.

## 3. Существенные разногласия (с атрибуцией)

1. **Q1: GO (прагматик) vs CONDITIONAL (аудитор, архитектор, реалист, скептик).** Прагматик: каркас доказан «в гневе» (окно, dirty-ro). Остальные: каркас не обёрнут вокруг каждой сессии; sentinel/RSS-цензус/pjdfstest-контракт не написаны. Разрешение: спор о моменте, не о модели — каркас = фаза 0, сессии только после.
2. **Топология стейджа:** 1 член (архитектор: прод-топология на file-backed невоспроизводима) vs 2 члена nvme/hdd (аудитор, прагматик, реалист: multi-device в батарее доказан только на 256–512M образах — стейдж растит покрытие бесплатно). **Решение: 2 члена.**
3. **Число копий:** одна расходуемая (большинство) vs вторая замороженная эталонная (скептик). **Решение:** одна + ZFS-снапшот zvols до первого маунта (= эталон посева) + манифест с выборочными sha256.
4. **Срок бэкапа незаменимого:** до первой write-heavy сессии даже на стейдже (скептик: индекс/курация STASH = work product) vs до первого rw живого пула (аудитор, прагматик, реалист). **Решение:** копию запускать сейчас; жёсткий гейт — первый rw живого пула; риск скептика погашен выносом БД STASH на ZFS.
5. **Пост-cutover календарь:** скептик сохраняет 24h soak ступени + 30 дней прод-soak; остальные — счётчики. **Решение:** счётчики + первая неделя прода с усиленным мониторингом и правом немедленного разворота; настройка гейтов прода — отдельное решение перед фазой 5.
6. **B1 in-place vs B2 migration:** реалист вводит B2 равной веткой; остальные неявно предполагают B1. **Решение:** ветка выбирается тремя измеримыми фактами (Q3), не предпочтением.

## 4. Решение

### Q1 МОДЕЛЬ АДАПТАЦИИ — **CONDITIONAL** (после фазы 0 — GO)

Модель: прогресс = экспозиция (ops, ГБ, сессии, покрытие классов операций), не календарь. «Чиним на лету» разрешено для кода, запрещено для данных.

Условия: (1) каркас автоматических гейтов (фаза 0) построен и всухую прогнан до первой сессии; (2) классификация находок: перф/errno/cosmetic → fix-on-the-fly, **corruption-class → write-freeze + kill-review**, §8 абсолютен; (3) правило «фикс → тест в батарею (падающий на пре-фикс артефакте) → счётчик заново» — монотонное ужесточение батареи заменяет монотонность 14 дней; (4) стартовые пороги экспозиции: ≥1 полный скан библиотеки или ≥10⁷ файлo-визитов, ≥5×10⁵ create, ≥3 чистые kill-9-дрели под реальной нагрузкой, ≥10 чистых session-end fsck, RSS плато/кап; (5) пиннинг билда: sha256 в ledger, пересборка только на границах сессий.

**Первый шаг:** расширить `scripts/regression.sh` (sentinel ~64 хэшей, RSS-захват, оп-цензус из `BCACHEFS_FUSE_LOG`, еженедельный pjdfstest) + скрипт-обёртка сессии — до посева стейджа.

### Q2 ПЕРВАЯ НАГРУЗКА — stash-GPU на стейдже — **GO**

- **Носитель:** 2 file-backed члена на zvols zdata (метки nvme/hdd), 0.5–1T (исключение из «≤2G» подписано, 15a фаза 2).
- **ZFS-снапшот zvols до первого маунта** = кнопка сброса + эталон посева.
- **Посев:** `rsync -aH --delete --checksum` (дрейф часов гостя +6ч20м — только чексуммы), без `-X`, через NFS-мост при работающей VM, throttled ночью; манифест + выборочные sha256. Далее ночная дельта, недельный reconcile.
- **Поток односторонний:** прод → стейдж всегда; стейдж = slave, выводы advisory.
- **Раскладка:** `library/` (чтение) + `stash-out/` на FUSE (запись); SQLite/БД STASH — на ZFS хоста (обход mmap-вопроса).
- **Обёртка сессии:** mount под `rlimit-run.sh` (rctl deny; стартовый кап 1 ГБ, калибровать) → snapshot pre → сессия (LOG вкл) → umount → **fsck-гейт** (nonzero = провал, счётчики в ноль) → snapshot post + RSS в ledger.
- **Фазирование:** A — scan-only (read-soak метаданных, слабейшая зона ×10.7); B — запись после зелёной A; DB-on-mount — только после mmap-аудита.
- **fd-057 не блокирует rw-стейдж**; для следующего касания живого пула нужны battery-assertion «все fd членов O_RDONLY по procstat при ro-маунте» + одно повторное чистое ro-окно (внешний счётчик + supers bit-bit).
- **Дрель одноразовости до первой GPU-сессии:** snapshot-clone → mount → verify → re-rsync поддерева.

**Первый шаг:** zvols → снапшот → ночной посев через мост (VM работает, нулевое касание пула) → дрель одноразовости.

### Q3 ПУТЬ К CUTOVER — **CONDITIONAL** (дерево)

- **Ветка A (расхождение-провал):** чексумма на ro-чтении / второй corruption-класс / RSS неограничен под капом → порт = ro-инструмент + research fork; VM не уходит. Честный выход.
- **Ветка B (сходимость):**
  - **B1 in-place** (базовая): окно — VM off → baseline **после** выключения → (opt) ro-verify [057 ✓ + assertion + повторное окно] → rw-маунт → флип `poolmount` (единственный) → сервисы по нарастающей, samba последней → откат ≤30 мин отрепетирован.
  - **B2 migration** (если dump-super diff противоречив ИЛИ использованный объём ≤ ~3T): свежая ФС нашим билдом после эвакуации через zdata-буфер; старая ФС = натуральный бэкап; убивает формат-риск ценой перекачки.
  - **Выбор B1/B2 — три факта** (снять заранее): dump-super format/compat diff наш билд vs VM-тулчейны; использованный объём пула; пиннинг дисков по серийникам.
- **Необратимость — тающий актив:** точка невозврата = первый rw-маунт живого пула (внутри B1 — первый incompat-бит за пределами VM-тулчейнов; проверка в момент cutover). После нативных записей откат = «VM-fsck чисто на пуле, который писали мы»; при двойном попечительстве — ежемесячный VM-fsck.
- **VM — единственный ремонтный цех** (наш fsck не чинил реальные повреждения): **не декомиссионируется, пока наш порт — писатель**. «Пенсионирование» = вывод моста; VM → cold-standby навсегда. Вывод из cold-standby — отдельное решение: (a) restore-дрель PASS, (b) 6 сервисов нативно на реальных данных, (c) подпись деградаций.

**Первый шаг:** снять три факта (dump-super diff; объём; camcontrol-пиннинг).

### Q4 БЭКАП-ПОЗИЦИЯ — **NO-GO сегодня → GO по чек-листу**

Перечня незаменимого нет, копии нет, restore не пробовался (15a #13 — вопрос владельцу). Нетронутый ro-пул сейчас сам себе бэкап — потому модель владельца и безопасна для старта.

Переход в GO: (1) владелец перечисляет незаменимое подмножество; (2) чексуммированная копия на zdata — физически отдельный диск от членов пула, **по серийникам**; (3) одна выполненная проба восстановления («бэкап = то, что один раз восстанавливали»); (4) процедура письменно, версии — zfs-снапшоты (нативные снапшоты bcachefs на BSD невозможны). Жёсткий гейт — первый rw живого пула; staging-фазы бэкапа не требуют.

**Первый шаг:** запустить копию незаменимого через мост **сейчас** (мост жив, нулевой риск) + запросить у владельца перечень — самое дешёвое из самых ценных действий независимо от всего остального.

## 5. План постепенной адаптации (гейты вместо календаря)

**Инварианты:** живой пул не-rw до гейтов Q3+Q4; §8 абсолютен; фикс = патч + тест в батарею + счётчик заново; corruption = write-freeze; бинарь пиннингуется; поток прод→стейдж односторонний; тяжёлое сериализовано под `nice 19` и rctl.

- **Ф0 Каркас** (блокер сессий): regression.sh + sentinel/RSS-цензус/pjdfstest; обёртка сессии; rctl-кап; канарейка statfs+touch (stall >10 с → алерт / авто-`umount -f` на прод-ступенях). Слои стопа L0 канарейка → L1 кап → L2 sentinel/fsck → L3 §8. *Выход:* обёртка всухую зелёная; красная ночь блокирует продвижение автоматически.
- **Ф1 Стейдж + посев** (параллельно: старт Q4-копии; перечень от владельца; три факта Q3). *Выход:* манифест сверен; дрель одноразовости зелёная; обёртка ловит грязный образ.
- **Ф2 stash scan-only:** ответ на RSS-вопрос в «событиях на ГБ чтения» (плато-кэш vs утеча — повторное чтение vs свежее). *Гейты:* полный скан чисто; 0 необъяснённых аномалий; fsck чист после каждого umount; RSS плато/кап.
- **Ф3 stash запись:** плановая kill-9-дрель ПОД сканом; p99-гистограмма vs базовая линия; счётчики create/rename/unlink/ГБ; A/B против моста — побочный продукт.
- **Ф4 Мульти-сервис стейдж:** navidrome (канареечный потребитель) → qbittorrent (write-storm) → amuled/amutorrent → **samba последней** (деградация подписана). Ступень = k чистых сессий с покрытием классов ops; откат = config-flip на NFS.
- **Ф5 Cutover:** B1/B2 по трём фактам → окно по window-протоколу (baseline после VM-off; supers bit-bit; внешний BIO-счётчик на первые прод-часы; откат ≤30 мин) → по-сервисный прод → неделя усиленного мониторинга (замена «30 дней soak») → мост в cold-standby. **VM — навсегда cold-standby.**
